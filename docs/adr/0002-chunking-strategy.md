# ADR 0002: Structure-Aware Chunking with Semantic Overlap

## Status
Accepted · 2026-11-05

## Context
Academic policy documents (handbooks, course catalogs, grading policies) contain hierarchical structures: numbered sections, clause definitions, prerequisite lists, and tabular fee schedules. 

A naive fixed-character or fixed-token chunking strategy (e.g. slicing strictly every 300 tokens without regard to headings) cuts long definitions and rules across boundaries. When a prerequisite clause or academic warning condition is split in half across two chunks, retrieval returns fragmented context, blurring critical policy constraints.

Furthermore, university policies evolve over time, leading to multiple editions (e.g., Undergraduate Academic Rules 2023 vs Academic Rules Handbook 2026). Without explicit version tagging, retrievers conflate superseded and current clauses.

## Decision
We enforce a structure-aware chunking strategy paired with metadata versioning:
1. **Hierarchical Boundary Splitting**:
   - Primary split on document sections and headings (e.g., numbered clauses `4.2 Academic Standing`).
   - Secondary split on paragraphs and list items.
   - Fallback sentence-boundary splitting with target token window of 400 tokens and 50 tokens overlap.
2. **Mandatory Chunk Metadata Schema**:
   Every chunk generated by the indexer stores:
   - `source`: document filename (e.g., `Academic_Rules_2026.pdf`)
   - `section`: heading name / clause identifier (e.g., `4.2 Academic Warning`)
   - `page`: 1-based source page number
   - `doc_version`: publication date or edition string (e.g., `2026-06`)
   - `superseded`: boolean flag indicating whether the document has been repealed (`true` for 2023 policy, `false` for 2026 revision).
3. **Retrieval-Time Metadata Filtering**:
   The API query pipeline applies `where={"superseded": False}` by default, preventing the retriever from returning repealed clauses unless the user explicitly requests historical information.

## Options Considered
1. **Fixed-Window Chunking (No Overlap)**: Slices sentences abruptly; causes severe recall drops on exact clause boundaries.
2. **Fixed-Window with Overlap (100 tokens / 20 overlap)**: Better boundary continuity but destroys clause context and inflates storage amplification unnecessarily.
3. **Structure-Aware Chunking (400 tokens, 50 tokens overlap)**: Preserves clause semantics, provides consistent heading context, and maintains high precision across exact-term and definitional queries.

## Consequences
### Positive
- Guarantees coherent policy clauses within single chunks.
- Enables accurate citations: `[source, section, page]` can be verified deterministically against retrieved passages.
- Eliminates "Failure Mode E" (answering with outdated policies) through metadata filtering.

### Negative / Trade-offs
- Requires robust heading and section detection in the extraction pipeline.
- Increases storage amplification moderately (approx 1.25x - 1.35x), which is well within persistent storage limits.
